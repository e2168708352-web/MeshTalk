断网、断基站，

MeshTalk 通过蓝牙把附近的设备连成一张网。没有服务器，没有账号，没有手机号。 消息可以经由中间设备多跳中继，把覆盖范围推到单台设备蓝牙半径之外。

Offline mesh messaging over Bluetooth LE. No account. No server.

Features

不依赖基础设施的通讯

核心链路完全走本地无线，不经过任何中心服务器。

蓝牙直连

设备之间直接建立 BLE 连接，不经过路由器、基站或运营商网络。

端到端加密

基于 Noise 协议协商会话密钥，支持前向保密；中间中继设备无法读取内容。

无需账号

不收集手机号、邮箱或任何身份信息。首次启动即生成密钥对，身份即公钥。

多跳中继

消息可由其他设备转发，逐跳扩展覆盖范围。链路中断时仍可尽力投递。

跨平台互通

Android 与 iOS 使用同一套 BLE 包格式与加密实现，两端可直接互发。

源码开放

完整源码可审计、可自行编译。不信任二进制的人可以自己构建一份。

How it works

三步建立一条链路

整个过程不需要联网，也不需要任何一方在线登记。

发现

开启蓝牙后，设备在附近广播自身标识，同时扫描同一服务标识的其他设备。

握手

建立连接后协商 Noise 会话，双方用公钥确认身份，生成临时会话密钥。

收发

消息加密后经 BLE 传输；超出直连范围时，由中间设备逐跳转发。

About this fork

为什么会有这个版本

官方 bitchat 应用在中国区 App Store 无法获取，部分用户没有渠道安装。 这个分支从官方开源仓库拉取源码自行构建，提供可直接安装的包。

非商业

不收费、无广告、无内购，不收集任何用户数据，不做用户画像。构建与分发由个人维护，没有商业主体参与。

源码可核验

代码取自官方仓库 permissionlesstech/bitchat 与 bitchat-android，未引入任何第三方代码。截至 2026-10-24 已与两端上游 main 完全对齐，可按 NOTICE 记录的地址逐文件比对。

协议与加密未改动

BLE 包格式、Noise 握手与端到端加密逻辑与上游一致。改动的只是品牌资产、Bundle ID、网络标识符常量，以及少量缺陷修复。

为什么与官方不互通

本分支使用独立的 BLE 服务 UUID、Nostr 事件类型与私信前缀，因此官方客户端不会发现本分支用户。目的是避免用户被针对性识别和批量屏蔽，不是要另立一套协议——底层包格式与加密完全一致。

本分支与 bitchat 项目及其维护者无隶属、背书或赞助关系，官方不为其提供支持。 截至 2026-10-24 已与两端上游完全对齐，后续会持续跟进官方的安全修复与协议变更。

Known limitations

先把话说清楚

以下是当前版本的真实状态，避免安装后产生误解。

已知限制

  • 与官方 bitchat 不互通。MeshTalk 使用独立的 BLE 服务 UUID、Nostr 事件类型与私信前缀，因此官方客户端不会发现 MeshTalk 用户，反之亦然。这是刻意的网络命名空间隔离，不是缺陷。
  • Android 包为 debug 签名。仅适合测试与侧载。正式分发必须使用自己的 release keystore，否则无法上架，也无法覆盖升级。
  • iOS 包未签名。需要重签后才能安装到真机。免费 Apple ID 签名的证书 7 天过期，到期需重新签名。
  • 真机验证已完成。已完成 Android ↔ iOS 跨平台与 Android ↔ Android 的真实设备通信验证，双向收发正常。验证范围是基础通信链路；分享扩展、后台唤醒、大文件传输等边界场景尚未逐项覆盖。
  • 蓝牙权限异常时请先重启设备。若系统设置中已授权但应用仍提示缺少权限，通常是系统蓝牙服务残留状态，重启设备可清除。
